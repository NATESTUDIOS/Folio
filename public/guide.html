01 / Getting started

Your first project in under a minute

Folio is designed to feel like an app — not a website. Everything works on a phone, everything is offline-ready, and there's no setup step between you and writing code.

The editor on first load — pick a project or start a new one.

What Folio is

Folio is a code editor that runs entirely in your browser. There's nothing to install before you start using it, no dependencies to configure, and no build pipeline to break. Open the site, sign in (or skip that and stay a guest), and start coding.

Every project you create lives in two places at once:

  • On your device, inside IndexedDB — this is what lets Folio work without internet, and it's what makes saving instantaneous.
  • On the server, when you're signed in — this is what makes sync, deploy, and collaboration possible.

If you're a guest, everything still works — but only locally. Nothing leaves your browser, so nothing can be deployed, shared, or recovered if you clear site data.

The very first thing you'll see

If you've never used Folio before, the editor loads to an empty state with a clear invitation: create a project or open an existing one. If you have projects from a previous session, the most recent ones are listed below so you can jump straight back in.

Tap New project. A short modal asks for a name and gives you a choice of starter templates:

Blank

An empty index.html, style.css, and app.js. Nothing else. Pure start.

Landing

A hero section, feature grid, and CTA. Perfect for a quick marketing page.

Todo

A working todo list with add, toggle, delete. Ready to show someone.

Blog

A clean typographic blog page with an article layout.

Pick one, tap Create, and you're in. Folio opens index.html automatically.

You don't need to save manually Folio auto-saves 2 seconds after you stop typing. The Ctrl + S shortcut exists if you want to force it, but you'll rarely need it.
02 / The Editor

Where you write the code

A full-featured code editor built on CodeMirror 6, tuned for touch first and thumb-typing second.

The editor with syntax highlighting, line numbers, and active-line highlight.

What's included out of the box

Folio's editor isn't a textarea with monospace text. It's a real code editor — with syntax highlighting for HTML, CSS, JavaScript, TypeScript, JSON, Markdown, Python, and more. It auto-indents, matches brackets, and highlights the line you're on.

Syntax highlighting

Real color for real languages. HTML tags, CSS selectors, JS keywords, JSON keys.

Undo & redo

Unlimited history. No "you can only undo 10 edits" limits.

Find & replace

Full-document search with regex, case-sensitive, and whole-word options.

Auto-format

One tap formats HTML, CSS, JS, JSON, and Markdown with Prettier.

The toolbar

Below the editor sits a persistent toolbar that puts the most-used actions one thumb-tap away. It's designed for a phone — you shouldn't have to reach for keyboard shortcuts or hidden menus.

The primary row has:

  • Save — force a save right now. Rarely needed but reassuring.
  • Undo / Redo — as expected.
  • Ctrl — a modifier latch (see below).
  • Find — opens the CodeMirror search panel.
  • Format — formats the current file.
  • More — reveals the secondary row.

The secondary row (revealed by More) has:

  • New — create a new file inline.
  • Copy / Cut / Paste — clipboard actions that work with selection.
  • Select — select the entire document.
  • Symbols — a compact symbol keyboard.
  • Commit — save a version snapshot.
  • Preview — run the project.
  • Host — deploy to a live URL.

The Ctrl latch — a phone-first invention

Physical keyboards have a Ctrl key. Phones don't. Folio fixes this with a Ctrl latch — a tap on the Ctrl button that "arms" the next key you type.

Tap Ctrl, then tap Z. That's undo. Tap Ctrl, then S — save. The same shortcut you'd use on a laptop, but with the modifier as a sticky toggle instead of a held key.

Supported latch combinations:

  • Ctrl + Z — undo
  • Ctrl + Y — redo
  • Ctrl + S — save
  • Ctrl + F — find
  • Ctrl + A — select all
  • Ctrl + C / V / X — copy, paste, cut
The latch cancels itself If you tap Ctrl and then don't tap a valid key, the latch clears. Or tap Escape. Either way, it won't get stuck.

Symbols — the ones phones hide

Every phone keyboard hides the symbols that code needs most: { } < > ; = & | $ #. Folio solves that with a symbol sheet that appears above the toolbar — 32 of them, all one tap away.

Open it with the Symbols button. Tap any symbol to insert it at your cursor. The sheet stays open so you can insert several in a row without re-opening it.

Editor preferences

Everything about how the editor looks and behaves is adjustable in Settings → Editor:

  • Font size (10–24px) and line height (1.2–2.0)
  • Tab size — 1, 2, 3, 4, or 8 spaces
  • Soft tabs — spaces instead of tab characters
  • Line numbers — show or hide the gutter
  • Word wrap — wrap or scroll horizontally
  • Active line highlight — subtle amber tint on the current line
  • Bracket matching — highlight matching pairs
  • Autosave delay — off, 1s, 2s, or 5s
  • Format on save — auto-run Prettier when saving
  • Emmet expansion — HTML abbreviation shortcuts

If you're signed in, editor preferences sync across every device you use.

03 / Files & folders

Structured like a real project

Folio's file tree behaves like your laptop's — except it fits in your thumb.

The sidebar

On the left (or behind the menu button on mobile) sits the sidebar. It has seven panels:

Files

Your full project tree. Drag to scroll, tap to open, expand folders inline.

Info

The project's dashboard — health, stats, deployments, meta tags, storage.

Search

Find text across every file. Shows the line, the match, and how many per file.

Versions

Your commit history. Every save-point you've committed, with diffs.

Changes

Files you've edited since the last commit. Save all with one tap.

Outline

Every heading, class, or function in the current file. Tap to jump.

Notes

Your project's notebook. Multiple notes, coloured, pinnable, autosaved.

Creating files and folders

Inside the Files panel there's a small action bar at the top with four buttons: New file, New folder, Import, and Collapse/Expand all.

You can create files with paths — src/app.js creates a folder called src and a file called app.js inside it. You never have to make folders manually before creating files inside them.

Nested folders work too: src/components/Button.jsx creates three levels in one shot.

Renaming and deleting

Hover (or long-press on mobile) any file or folder to reveal the inline actions: Rename and Delete. Deleting a folder deletes everything inside it, with a confirmation showing how many files will be affected.

Deletes are permanent There's no trash bin. If you want a safety net, commit before you delete anything — that way you can restore the file from version history.

Importing files

You don't need to retype your existing code. Tap Import and Folio opens your device's file picker — pick one file or several at once. Text files are imported as-is. Images, PDFs, and other binaries are stored as data URLs so they live alongside your code and count toward storage.

Every imported file lands in the root of your project. If you want it nested, rename it after import or create it fresh with a path.

Filtering and expanding

Above the tree there's a filter input. Type any substring and the tree prunes to matching files — it searches the full path, so typing css finds style.css and src/main.css alike. The Expand all button opens every folder; Collapse all closes them all.

How notes work behind the scenes

Notes are stored as a special file called notes.json. It's hidden from the file tree — you never see it in the sidebar, so you can't accidentally edit raw JSON and break it. But it lives alongside everything else, counts toward your storage, syncs to the server, and comes along when you export the project.

04 / Preview

See your project run

Three ways to preview, each designed for a different moment.

Fullscreen preview with an in-app console at the bottom.

The three preview modes

Tap the Preview button to run your project. But the caret next to it opens a menu with three modes:

Fullscreen

A dedicated full-screen view with an in-app console that shows console.log output. Best for testing.

New tab

Opens in your browser's own tab. Best when you want the real browser environment.

Mini panel

A floating mini-window in the corner. Best for live-updating while you edit.

Your choice is remembered. The next time you tap Preview, it uses the same mode.

What happens under the hood

When you preview, Folio:

  1. Finds your HTML file — preferring index.html at the root, then any index.html nested deeper, then any HTML file at all.
  2. Inlines every linked CSS file directly into a <style> tag.
  3. Inlines every linked JS file directly into a <script> tag.
  4. Injects a small console bridge that forwards console.log, console.warn, and console.error to the preview pane.
  5. Injects any meta tags you've set for the project.

The result is a single self-contained HTML document that runs identically to how it would if deployed. This is why preview is a genuinely reliable check — it's not a simulation, it's the real thing.

Console logs appear in fullscreen preview If something isn't working, open fullscreen preview and watch the bottom pane. Your console.log("here") debug statements show up exactly as they would in devtools.

Multiple HTML files

If your project has more than one HTML file — say index.html and about.html — Folio previews the one you've chosen as "primary." You can set that in the Info panel.

If you haven't set a primary file, Folio prefers index.html at the root. That's usually what you want. If your entry point is named something else (home.html, main.html), set it explicitly.

05 / Projects

The home for everything you build

Every project you create lives here — organised, searchable, and filtered for the way you actually work.

The projects page — sortable, filterable, expandable per project.

Six tabs for six mindsets

At the top of the projects page sit six tabs, each showing a subset of your work:

  • All — every project that isn't archived.
  • Pinned — the ones you've starred.
  • Owned — projects you're the owner of.
  • Shared — projects someone else owns but has invited you to.
  • Public — projects whose profile visibility is set to public.
  • Archived — projects you've set aside.

Shared projects show a notification badge if you have pending invites. Pinned projects float to the top of every tab.

The storage bar

Below the header sits a compact bar showing your plan-wide storage:

  • Total used / total limit
  • Percentage
  • Colour-coded: green (healthy), amber (getting full), red (nearly full)

It updates every time you return to the page. No need to dig through settings to see how much space you have.

The project card

Each project appears as a compact card. The card always shows:

  • Project icon and name
  • Your role (Owner / Editor / Viewer)
  • Live status (deployed or not)
  • Storage used
  • View count
  • Last modified time

Tap the chevron on the right side of any card and it expands inline to show:

  • Full description
  • Language breakdown (e.g. "HTML 45%, CSS 30%, JS 25%")
  • A detailed storage bar with used/limit
  • Warnings for expired deployments or near-full storage
  • Three action buttons: Editor, View, Delete

The three actions

When you expand a card, three buttons line up horizontally:

Editor opens the project in the code editor. Fast path if you just want to write code.

View opens the project dashboard — health, deployments, commits, meta tags, and everything else. Fast path if you want to manage rather than edit.

Delete opens a typed confirmation dialog where you must retype the project name exactly. This prevents accidental deletion — you can't just tap "delete" and lose a project forever.

Search and sort

A search box in the header searches across project names, slugs, descriptions, and languages. It filters live as you type.

The sort button opens a filter panel with these sort options:

  • Modified — most recently edited first
  • Created — newest first
  • Name — alphabetical
  • Storage — biggest first
  • Recently deployed — newest deploys first
  • Most visits — highest traffic first

Filters

The same panel has filter toggles that narrow the list:

  • Deployed / Not deployed
  • Storage > 70%
  • Recently edited (last 7 days)
  • Never deployed
  • Expired deploys
  • Editor / Viewer / Commenter (for shared projects)

Active filters show as removable chips below the search bar. A Clear all button resets everything.

Creating projects — the simple way

The New button opens a single-screen modal. You give the project a name, optionally a description, pick a template, and tap Create. That's it.

If you want to customize the icon at creation time, expand the "Customize icon" section and pick from five generated presets, or upload your own image. If you skip it, the project gets initials with a coloured gradient — perfectly good as a starting point, changeable later.

Archiving

Every project's action menu has an Archive option. Archiving moves a project out of All / Owned / Shared / Public and into the Archived tab.

Archives are local-only — they don't sync to the server. That means archiving a project on your phone doesn't hide it on your laptop. It's a personal "out of sight" toggle, not a shared state change.

Unarchiving is the same button, now labelled Unarchive, from the Archived tab.

Pinning

Pin up to 3 projects you're actively working on. Pinned projects appear at the top of every tab (except Archived). Tap the bookmark icon on any project card or in the action menu to pin or unpin.

Pins are stored locally Like archives, pins don't sync across devices. Each device has its own pinned set.
06 / Project dashboard

One project, all its details

Every project has a full dashboard behind it. Health, deployments, commits, meta tags, collaborators, storage — organised into tabs you can navigate from anywhere.

The project dashboard — health card, live URL, and quick actions at a glance.

The health card

At the top of every dashboard is a single card that tells you how healthy the project is. It's colour-coded and shows at a glance:

  • Whether the project is synced to the server
  • Whether it's deployed (and when it was last deployed)
  • How much storage it's using
  • Whether traffic is flowing

Green means healthy. Amber means something to watch — a warning that's not critical yet. Red means something is broken or full.

Overview tab

The default landing shows:

  • The health card
  • Four stat tiles: files, commits, storage, last modified
  • An analytics strip: today's visits, 7-day total, all-time total, top page, and a tiny bar chart
  • A live URL card with a page selector
  • A details card with the project icon, name, slug, ID
  • Recent activity from the project's log
  • A meta tags form (collapsible)

The live URL card

Once your project is deployed, this card lets you jump to any page in it. The dropdown lists every HTML file in your project; pick one and the URL below updates to that page's specific address. A copy button puts the URL in your clipboard; an Open button opens it in a new tab.

For projects with only index.html, the selector shows one entry. For projects with several pages, you get a full navigator.

Deployment list

The Deploys tab lists every deployment your project has ever had. Each row shows the deployment's version, state (Live / Offline / Ready), timestamp, and actions:

  • Open — visit the deployment's URL
  • Copy URL — copy the deployment's specific URL
  • Redeploy — switch the live site back to this version
  • Delete — remove this deployment record

Deployments more than 30 days old are eligible for cleanup — Folio can auto-clean them periodically to keep your history tidy. You can also clean them manually.

Meta tags — social sharing that works

When someone shares your deployed project on Twitter, Slack, WhatsApp, or Discord, those apps look for specific HTML meta tags to build a preview card. Folio lets you set them without writing HTML manually.

The Meta Tags card has fields for:

  • Title — page title, also used for OG
  • Description — page description, also used for OG
  • OG image URL — the image shown in link previews (must be HTTPS)
  • OG type — website, article, or profile
  • Twitter card — summary or summary_large_image

When you save these, they're stored server-side and injected into every preview and every deployment automatically. You don't need to touch your HTML — Folio handles the injection.

The Info panel in the editor

You don't have to leave the editor to see any of this. The Info panel in the sidebar mirrors the dashboard's key data — health, stats, deployments, storage, meta tags — so you can check status while editing without losing your place.

There's also an Open dashboard button at the top of the Info panel — tap it and you jump to the full dashboard in one action.

07 / Commits

Version history without git

Folio gives you the safety net of version control without the complexity of branches, remotes, or merge conflicts.

What a commit is

A commit is a snapshot of your entire project at a moment in time. Every file, captured together, so you can always come back to exactly what the project looked like at that point.

Unlike git, Folio's commits are linear — there's no branching, no merge conflicts, no "detached head." You commit, you keep working, you can restore any past commit if you need to.

Making a commit

There are two ways:

  1. Tap the Commit button in the editor toolbar. A modal opens showing all files changed since your last commit, with line counts.
  2. Folio auto-generates a commit message based on what changed (e.g. "edit: app.js (+12, −3)"). You can edit it or accept it.
  3. Tap Commit and the snapshot is saved.

You can also open the Commits tab on the project dashboard and tap Commit now if you have uncommitted changes.

Browsing history

Every commit is listed newest-first with:

  • The commit message
  • Files changed count
  • Additions and deletions
  • When it was committed

Auto-snapshots (created before a restore) are marked with a distinct badge so you can tell them apart from your own commits.

Comparing two commits

Tap Diff on any commit to see what changed between it and the previous one. Folio shows file-by-file diffs with colour-coded additions and deletions — green lines added, red lines removed, amber lines changed.

Redeploying an old commit

Tap Redeploy on any commit and Folio switches your live site back to that exact version. Perfect for rolling back a bad deploy in seconds.

Restoring to your editor

Tap Restore and Folio rewrites your entire project to that commit's snapshot. Before it does, it automatically creates a snapshot of your current state — so even restoring is reversible.

Restoring affects the whole project Restore replaces every file with the snapshot version. Files created after that commit are removed. Files deleted after that commit come back.

Clearing all versions

If you want a clean slate, the Danger zone in the dashboard has a "Clear all versions" button. Files stay; only the snapshot history is deleted.

08 / Notes

A notebook inside every project

Every project has its own notes panel — not one giant text field, but a proper list of individual notes you can write, colour, pin, edit, and delete.

Why multi-note

Most "project notes" features give you a single text field. That works for one paragraph. But real projects have many thoughts: a README draft, a TODO list, a snippet you'll want later, a design decision you need to remember.

Folio's notes system treats each idea as its own note — colour-coded, timestamped, pinnable, searchable.

Creating and editing

Open the Notes panel from the editor sidebar. Tap New note. A fullscreen editor opens with:

  • A title field at the top
  • A monospace body for writing
  • A word counter in the footer
  • Pin, colour, and delete actions in the header

Notes auto-save 800ms after you stop typing. The footer shows "Editing…" while typing, then "Saved" when the save completes.

Titles derive from content

If you don't give a note a title, Folio looks for the first line starting with # and uses that as the title. So a note that starts with # Meeting notes shows up in the list as "Meeting notes" — without you having to fill in a separate field.

Six accent colours

Notes can be tinted to help you sort by type:

  • Amber — general notes
  • Sky — reference
  • Violet — ideas
  • Emerald — done / archived thoughts
  • Rose — warnings
  • Cyan — snippets

Each note's colour shows as an accent bar down the left of its card in the list. Easy visual scanning without reading every title.

Pinning

Pin the most important note to the top of the list. Unpinned notes sort by last modified below pinned ones.

Storage implications

Notes count toward your project's storage — but as data, not as files. The notes.json file is small. A thousand notes of a few hundred words each would be under 100 KB total.

Notes survive export

When you export a project as .folio or .zip, your notes come with it. They're also excluded from the deployment payload — meaning your private notes never end up on your public live URL.

Every file type, rendered properly

The viewers

Images

PNG, JPG, WebP, GIF, SVG. Displayed at full size, scaled to fit, with the file size shown above.

PDFs

Embedded in an inline reader. Scroll through the document without leaving Folio.

Video

MP4, WebM, OGV. Full player controls, plays inline.

Audio

MP3, WAV, OGG, M4A. Compact player with play/pause and seek.

Text

Plain text files rendered in a readable monospace view — no syntax highlighting clutter.

Fonts

WOFF, WOFF2, TTF, OTF. Shown as an info card with the font's name and a download link.

Code files open in the editor

Uploading media

You can import any of these file types. Images, PDFs, videos, and audio are stored as data URLs inside your project, which means they're available offline, sync with your project, and work identically on the deployed site.

Upload limits Individual files can be up to 5 MB. Total project storage is 10 MB (or higher depending on plan). If you're adding a large image or video, you'll see the storage bar rise immediately in the project Info panel.
10 / Collaboration

Share a project with someone else

Folio's sharing system lets you invite other people to work on a project with granular roles.

Three roles

When you invite someone to a project, you pick a role:

RoleCan do
Viewer Read files, see project info, download public assets. Cannot edit.
Commenter Everything a viewer can, plus leave comments. Cannot edit code.
Editor Read and write. Can edit files, commit, deploy, change settings.
Owner Everything an editor can, plus delete the project, manage collaborators, transfer ownership.

Inviting someone

From the Sharing tab in the dashboard, tap Invite. Enter:

  • Usernames — comma-separated for bulk invites
  • Role — viewer, commenter, or editor

Tap Send. Folio sends each invited user a notification. If you invited one person, you get a success modal with a direct invite link you can copy and share via any channel. If you invited several, you get a summary with copyable links per user.

Pending invites

The Sharing tab lists pending invites you've sent that haven't been accepted yet. Each shows:

  • The invited user's ID (truncated)
  • The role you assigned
  • Days until expiry (default: 7 days)
  • Buttons to copy the invite link or cancel the invite

Pending invites refresh automatically every 30 seconds while you're viewing this tab.

Removing a collaborator

Below the pending invites list sits every active collaborator. Tap the trash icon next to any of them to remove their access. They're notified immediately.

Visibility axes

The Sharing tab also has five visibility toggles for making parts of your project public:

  • Show in profile — appear on your public profile page
  • Live site link — show a "Visit live site" button on the shared link
  • Code viewer — let anyone read your source files
  • Language breakdown — show language percentages
  • JSON database API — let external apps read your JSON data

Each is independent — you can have a public site with private code, or public code with a private site. Whatever fits the project.

API keys

Every project can generate an API key. This key lets external services call the project's JSON database or trigger deploys without a user session. Generate one from the Sharing tab. The key is shown once — copy it immediately. Regenerating invalidates the old key.

11 / Deploy & host

Your project, on the internet

Deploy any project to a live URL with one tap. No build steps, no configuration, no CI.

A deployed project with its live URL and history visible.

What deploy does

When you tap Deploy, Folio:

  1. Collects every file in your project.
  2. Applies your meta tags to the primary HTML file.
  3. Uploads everything to a hosting server.
  4. Returns a live URL that serves your project.

The whole thing takes a few seconds. When it's done, you have a real URL that loads your project exactly as it does in preview.

Where the URL lives

Every deploy gets a URL on Folio's hosting infrastructure. If you want a specific path, your project's slug becomes the path — so a project called "Coffee Shop" with slug coffee-shop gets a URL at your-subdomain.foliostudios.vercel.app/coffee-shop.

You can always find the exact URL in the project dashboard's live URL card, or in the Deploys tab.

Redeploying

Deploy as many times as you want. Each deploy creates a new deployment record. The previous deployments stay in history — you can roll back to any of them from the Deploys tab.

Taking offline

If you want to take a project offline temporarily without deleting it, use Take offline. This removes the live URL but keeps your files, deployments, and everything else. Redeploy any time.

Deploying requires an account Guests can build and preview but not deploy. Every deployed URL is tied to your account.

Deploy limits

Each project can be deployed up to 10 times per hour. That's plenty for normal use — but if you're rapidly iterating, you'll hit the ceiling. Wait a bit and try again.

Automatic meta tags

When you deploy, Folio injects your meta tags into the primary HTML file automatically. So the deployed site always has correct OG title, description, and image — even if you never touched the HTML.

This is different from preview injection (which is in-memory only). Deploy writes the tags into the actual file that's served, so social media crawlers see them.

12 / Tools

A workshop next to your editor

Folio includes a suite of small web-dev utilities — image generation, colour tools, QR codes, JSON formatting, and more.

The tool grid

Visit /tools and you'll see every tool as a card in a searchable grid. Tools are organised by category:

  • Images — image generator, QR codes, colour tools
  • Text — font preview, markdown preview, base64
  • Data — JSON formatter
  • Network — API tester

Use the search bar to filter by name, or click any tool card to jump straight to it.

Deep links

Every tool has a direct URL: /tools?tool=qr, /tools?tool=color, /tools?tool=json. Share the URL with someone and they'll land on that specific tool.

The image generator

Folio's image generator is powered by Flier and produces polished images from templates. You can use it to create:

  • Social media graphics
  • Quote cards
  • Event posters
  • Feature blocks
  • Product grids
  • Anything with a title and a background

Pick a template, enter text, choose a size, set colours, and download a PNG. Everything renders server-side so the output is crisp regardless of your device.

QR codes

Generate a QR code for any URL or text. Pick a size, pick error correction level, pick colours, and download. Works offline — the QR renderer runs in your browser.

JSON formatter

Paste any JSON and get it formatted, validated, or minified. Errors are shown inline with line numbers.

API tester

Send HTTP requests to any CORS-enabled API. See the status code, response time, and full response body. Perfect for debugging an endpoint before wiring it into your project.

Color tools

Pick any colour, see its hex/RGB/HSL values. Check WCAG contrast between any two colours. Browse Material and Tailwind palettes with one tap to copy any swatch.

Insert directly into your project Most tools have an "Insert" button that pushes their output into the editor. Generate a QR code, insert it, done — no download-then-upload dance.
13 / Analytics

See who's visiting what

Every deployed project tracks anonymous visits, page views, and API usage. It's private, aggregated, and never sold.

How tracking works

When your project is deployed and someone visits it, Folio's analytics script fires once. It sends:

  • The project ID
  • The page path they visited
  • The referring URL (where they came from)

Nothing else. No fingerprinting, no IP storage, no personal data. The visit is counted, aggregated into daily buckets, and that's it.

What you see

The project's Overview tab shows an analytics strip with:

  • Today's visit count
  • 7-day total
  • All-time total
  • Top page (the URL with the most views)
  • A tiny sparkline chart of the last 7 days

Open the Analytics tab for the full picture: 7-day trend chart, top pages list, DB operations count, API call count. All refresh on demand.

The account-wide analytics page

Visit /analytics from the rail to see:

  • Overview — total views across all projects, top projects, storage summary, recent activity
  • Projects — per-project breakdown with views, DB ops, API calls, storage
  • Profile — your public profile page views (7-day and 30-day charts)
  • Activity — recent events across all projects
  • Logs — your own action history (logins, edits, deploys, settings changes)

Rate limits

Analytics fetches are cached for 5 minutes. The Projects and Overview tabs only fetch the first 10 projects' data to avoid hammering the server. If you have more, they don't affect the displayed totals but you can scroll to see individual projects in the Projects tab.

What's on your profile

15 / Settings

Every switch, every preference

One page for appearance, editor defaults, account security, notifications, and everything else.

Ten sections

The Settings page has ten tabs across the top:

  • Appearance — theme, text size, reduced motion, font family
  • Editor — typography, indentation, display, behaviour, diagnostics
  • Account — email, username, password, sessions
  • Notifications — push settings, what to get notified about
  • Storage — per-project usage, cache management
  • Database — IndexedDB diagnostics, export, reset
  • PWA — install, update, cache
  • Data — export/import settings, about your data
  • Advanced — debug mode, sync queue
  • Danger — clear cache, reset all settings, sign out

Appearance

Theme switches between dark, light, or auto (follows your OS setting). Text size scales the entire app from 85% to 135% — useful on small phones or when you want to see more code at once. Reduced motion disables animations across the app. Font family switches between Inter and the system UI font.

Editor

Every editor preference discussed earlier — font size, line height, tab size, soft tabs, line numbers, word wrap, active line highlight, bracket matching, autosave delay, format on save, emmet, JSON lint, JS lint. Each has a live preview so you can see what you're configuring.

Account

Change your email, username, and password. Each change requires your current password and generates a security notification to your device — so if someone else got into your account, you'd know immediately.

Notifications

Enable push notifications, then choose what categories you want to receive:

  • System alerts — maintenance, feature announcements
  • Analytics thresholds — traffic spikes, milestones
  • Database writes — when your JSON DB is modified
  • Storage limits — when projects approach their limits
  • Project activity — commits, deploys, offline state
  • Invites — when someone invites you to collaborate
  • Security events — password changes, new logins, blocked requests

Each toggle is independent. You can have deploy alerts but not analytics, invites but not storage, whatever fits.

Storage

Shows your browser storage breakdown: how much space your projects are using, what quota you have, whether persistent storage is granted. Lists each project with its individual usage. A cleanup section helps you find projects over 90% and either delete files or archive the project.

Database

A diagnostics panel for power users. Shows:

  • Schema version (code vs actual)
  • All six stores: projects, files, versions, projectMeta, syncQueue, folders
  • Record count and size per store
  • Export button — download a JSON snapshot of everything
  • Reset button — wipe the local database entirely

You'll rarely need this. But if a project ever fails to load, or a stale record hides somewhere, this panel is where you can inspect and fix it.

PWA

Install Folio to your home screen. Check for updates. Clear the app cache. Every PWA thing in one place.

Data

Export your settings as a JSON file, or import them on another device. Import project backups from the Projects page. Read about how your data is stored.

Danger

Clear local cache (removes offline copies but not server data). Reset all settings (back to defaults — you stay signed in). Sign out. Every destructive action here requires explicit confirmation.

16 / Real stories

What people actually do with it

Folio isn't a demo. Here are real workflows that people use it for every day.

Story 01

The midnight idea. It's 11pm and you've got an idea for a landing page for a friend's business. No laptop in reach — but your phone is on the nightstand.

You open Folio, pick the Landing template, edit the headline, change the primary colour, swap in a photo from your camera roll, tap Deploy. By 11:04pm the URL is live and you've sent it to your friend. They see it in the morning.

Story 02

The bug that had to wait. You're on the train. Offline. You've been chasing a bug in your portfolio site for two days and it's finally clicked — the CSS grid is collapsing because one child has a minimum width.

You open Folio (works offline), find the CSS file, fix the grid property, commit the change. You don't have service but the commit is local. When you arrive home and the phone connects to WiFi, the change syncs. You deploy from the laptop. Done.

Story 03

The collaborator. Your friend is a designer. You're not. They want to tweak the colours of your side project. You don't want to give them your editor and let them touch the JS.

You go to the Sharing tab, invite them as Editor. They accept the invite, open the project on their laptop, change the CSS. You get a notification. You review the diff in the Versions tab. Everything looks fine. You deploy.

Story 04

The regression. A deployment went out and now the site looks broken. You're not sure which change broke it. You have 12 commits and no time to read all of them.

You open the Commits tab on the dashboard. You find the last commit that was clearly working — the one from yesterday morning. You tap Redeploy. Live site is restored to yesterday's version in seconds. Now you have time to actually debug.

Story 05

The reference dump. You're building a small web app and you keep looking things up — the exact syntax for CSS Grid, the em-based breakpoint pattern, the JSON structure for a todo item.

You create a project called "Reference", make 20 notes with titles like "CSS Grid layout", "Flexbox centering", "JSON schema example". Each note has a # heading at the top and the code below. Now every time you need to look something up, you open Reference and scan the note list. No more googling.

Story 06

The email invite. You're building something with a friend who lives in another city. You don't have their phone number but you have their Folio username. You invite them. They get a push notification on their phone within seconds. They accept. Your project now has two collaborators.

Every commit either of you makes generates a notification. Every deploy gets announced. You stay in sync without ever having a real-time video call.

Story 07

The image drop. You're building a recipe card layout. You want a photo of the actual dish. You take the photo with your phone, import it into Folio, and reference it in the HTML as a data URL. The project still lives entirely in one place, still previews identically to how it deploys, still syncs across devices.

No CDN. No image host. No separate upload step.

Story 08

The shareable link. You've built a small calculator. You want to send it to someone. You don't send the code — you send the live URL from the Deploys tab. They tap it on their phone. It opens. It works. Nothing about their environment matters because it's just HTML, CSS, and JS.

Story 09

The backup. You're about to try something risky — a big refactor. Instead of worrying about whether you can undo it, you commit first. Then you make the changes. If it works, great, commit again. If not, restore. Either way, you're never more than one tap from yesterday's version of your project.

Story 10

The JSON backend. You're building a small app that needs to store data — user preferences, todo state, whatever. You don't want to run a real backend. Folio gives each project a JSON database with a simple HTTP API. You write 4 lines of JavaScript to save and load data. It works. It's live. Total time from idea to working app: 20 minutes.

The common thread Every one of these stories is possible because Folio works offline-first, deploys in one tap, and never loses your work. That's the whole point — remove the friction between wanting to build something and having it live on the internet.

Using the Ctrl latch

On a phone or tablet, tap the Ctrl button in the toolbar to latch the modifier, then tap the key you want to combine it with. The latch clears itself automatically after one shortcut.
